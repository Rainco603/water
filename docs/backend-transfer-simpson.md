# 定流量输送体积计算（二阶辛普森积分 + Kahan 求和）后端对接文档

## 一、需求

升级「定流量输送」的体积累积算法，从简单累加改为**二阶辛普森（Simpson）积分**，并要求：

1. 采集数据：**时间、瞬时流量、温度**三要素，连续采样；
2. 三点齐备时用 $\Delta V=\frac{t_2-t_0}{6}(q_0+4q_1+q_2)$ 计算区间体积增量；
3. 采样点不足三点时自动降级为**梯形法**过渡；
4. 用 **Kahan 求和**累加体积增量，消除浮点数长期累积精度损失；
5. 利用温度计算水的**密度**，可按需扩展累积**质量**；
6. **数据预处理**：过滤超量程、负值、时间间隔过大的异常数据；长时间断连时**清空采样缓存队列**，重新收集采样点；
7. 累积体积用于定流量输送达标判定，到达设定值后触发执行器控制。

## 二、为什么必须后端做

| 环节 | 执行方 | 说明 |
|---|---|---|
| 瞬时流量/温度的**连续高频采样** | 后端 | 前端页面被切换/后台节流时无法保证每秒采样；前端拿到的只是轮询快照 |
| 体积积分 + 达标判定 + 触发关泵 | 后端 | 当前已由后端 `/auto-transfer` 任务线程完成；算法升级只是替换其中的累积逻辑 |
| 断连期间的连续数据 | 后端 | 后端常驻才能持续追踪时间间隔、判断断连与清缓存 |

结论：前端只能「启动任务 + 展示结果」，积分过程必须留在后端。前端**无需改动**（除可选展示新字段）。

## 三、当前后端行为契约（前端已观测到，改动时不要破坏）

| 接口 | 行为 |
|---|---|
| `POST /auto-transfer` | 请求体 `{source, target, device, target_liters}`，返回 `{id,...}`；已有进行中任务返回 **HTTP 409**；开泵指令下发失败返回 **HTTP 500** |
| `GET /auto-transfer/:id` | 返回任务对象：`status`（`running/done/stopped/failed`）、`accumulated_liters`、`flow_total`、`fail_reason` |
| `POST /auto-transfer/:id/stop` | 手动停止 |
| `DELETE /auto-transfer/:id` | 删除记录（运行中拒绝） |
| `GET /auto-transfer` | 列表 `{code,total,page,page_size,data}` |

`fail_reason` 现有枚举：`zero_flow`（零流量/断流）、`timeout`（超时未达标）、`send_fail`（开泵下发失败）、`server_restart`（服务重启中断）。

## 四、后端改动清单

### 1. 采样数据源与节奏

任务运行期间，从现有传感器数据通道按固定间隔读取**瞬时流量 `q`（统一单位 L/s）**与**水温 `T`（℃）**，连同本地时间戳 `t`（Unix 秒）组成采样点 `(t, q, T)`。

- 建议采样间隔：`1s`（与积分公式量纲匹配，且足够平滑）；
- 独立于前端的轮询快照，任务线程自己采样，保证断连时可感知。

### 2. 数据预处理（异常过滤 + 断连清缓存）

每个采样点先过预处理，不合格直接丢弃，不进入积分：

```python
def preprocess(t, q, T):
    # 非法/超量程/负值 → 丢弃
    if q is None or q < 0 or q > MAX_FLOW_LS:      # MAX_FLOW_LS 按量程配置
        return None
    if T is None or T < MIN_TEMP or T > MAX_TEMP:   # 超范围温度丢弃，用上一次有效温度插值
        T = last_valid_T
    if last_sample is None:
        return (t, q, T)
    dt = t - last_sample.t
    if dt <= 0:                                     # 时间戳不递增 → 丢弃
        return None
    if dt > MAX_SAMPLE_GAP:                         # 长时间断连 → 清空缓存，重新收集三点
        clear_queue()
        return None
    return (t, q, T)
```

> 关键语义：**断连清空采样缓存队列**——长时间没有有效数据后，重新从零收集三点再开始积分，避免用「跳变后」的错误区间做抛物线拟合。

### 3. 体积增量积分（二阶辛普森，三点齐备）

缓存队列里**连续三个有效采样点** `(t0,q0)`、`(t1,q1)`、`(t2,q2)` 齐备时：

$$\Delta V=\frac{t_2-t_0}{6}(q_0+4q_1+q_2)$$

- `t` 为秒、`q` 为 L/s，则 `ΔV` 单位为 **升（L）**；
- 该公式为等距三点的抛物（辛普森 1/3）规则，要求 `t1 ≈ (t0+t2)/2`。若采样固定 1s 间隔则天然等距，直接可用；若因丢点导致不等距且偏差较大，用通用三点抛物线（拉格朗日）或按第 4 条降级为梯形，避免错误外推；
- 积分后弹出 `(t0,q0)`，保留 `(t1,q1),(t2,q2)`，等下一个新点凑齐下一段三点。

### 4. 不足三点：梯形法过渡

队列不足三点时（任务刚启动、或断连后重新收集的过渡期），退化为梯形法，保证进度从第一秒就连续：

$$\Delta V=\frac{t_1-t_0}{2}(q_0+q_1)$$

### 5. Kahan 求和累加体积增量

每次算出的 `ΔV` 用 Kahan 求和累加，消除长任务中浮点小增量被截断的精度损失：

```python
comp = 0.0
volume = 0.0

def accumulate(dv):
    global comp, volume
    y = dv - comp
    t = volume + y
    comp = (t - volume) - y
    volume = t
    return volume
```

`volume` 即 `accumulated_liters`，供前端进度条与达标判定使用。

### 6. 温度 → 密度（可选质量累积）

按需计算累积质量（`kg`）。水温 `T`（℃）下水密度 `ρ`（kg/m³）在 0~40℃ 范围的经验公式：

```python
def water_density(T):
    return (999.8395 + 16.945176*T - 7.9870401e-3*T**2
            - 46.170461e-6*T**3 + 105.56302e-9*T**4 - 280.54253e-12*T**5)

mass_kg = water_density(T) * volume_L / 1000   # 1 m³ = 1000 L
```

- 不启用质量时，采样仍可带上温度，仅用于第 2 条的温度过滤与可选日志；
- 建议在任务对象里加只读字段 `accumulated_mass`（可选，前端不依赖它也能工作）。

### 7. 达标判定与执行器控制（保留现有语义）

在采样/积分循环里做判定，沿用现有状态机：

```python
if volume >= task.target_liters:
    send_control(task.device, OFF, source='transfer')
    task.status = 'done'
    clear_queue()
```

- 保持 `zero_flow`（长时间无有效流量）/ `timeout` 等既有失败原因逻辑；
- **手动停止**（`stop`）与 **服务重启** 路径不变，停止/中断时同样 `clear_queue()`，避免下次任务复用过期采样点；
- 409（任务占用）与 500（开泵失败）语义不变，前端无需感知差异。

## 五、接口（无需新增）

沿用现有全部接口；可选增强（不破坏兼容）：

- 任务对象增加字段：`accumulated_mass`（累积质量，kg）、`algorithm: 'simpson_v2'`（算法版本，便于前端/日志确认走的是新算法）；
- 列表接口返回时带上上述字段即可，前端按 `data` 透传展示。

## 六、联调测试用例

1. **恒流 1 L/s、连续 5 秒**：期望体积 ≈ 5.0000 L（辛普森对一次曲线精确，误差≈0），验证公式与单位换算正确。
2. **流量缓慢变化的模拟数据**：以固定 1s 间隔喂入递增流量序列，与梯形/辛普森手工计算对比，验证 ΔV 与累加值。
3. **降级过渡**：任务启动前 2 秒（仅 1~2 个点）用梯形法，第 3 秒起切换辛普森，进度不跳变、无 NaN。
4. **异常过滤**：喂入负流量、超量程流量、超范围温度 → 该点丢弃，体积不跳变。
5. **断连清缓存**：采样中断 > 阈值后恢复 → 缓存清空，重新收集三点前体积不累计错误区间。
6. **Kahan 精度**：用极小 ΔV（如 1e-6 L）累计 10 万次，累加值与高精度参考值对比，误差远小于朴素逐次相加。
7. **达标触发**：目标 5L、恒流 1L/s → 第 5 秒 `status='done'` 且下发关泵指令；前端进度条走满、弹「已完成」。
8. **回归**：手动停止、409 并发占用、500 开泵失败、`fail_reason` 各枚举仍按原语义返回，前端不回归。

## 七、给前端的一句话结论

后端按上述实现后，前端**一行不用改**——`POST /auto-transfer` 启动、`GET /auto-transfer/:id` 轮询 `accumulated_liters` 与 `status` 即可；若后端加了 `algorithm`/`accumulated_mass` 字段，前端可选用「仅展示」。
