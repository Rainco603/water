# 后端对接文档：定流量自动输送 + 历史计时数据

> 目标后端：Python / Flask 服务（本仓库外的独立服务）
> 前端调用约定：baseURL `/api`，统一返回 `{ code, msg, data }`，`code === 0` 成功；
> 时间格式 `YYYY-MM-DD HH:MM:SS`；分页接口返回 `{ code, total, page, page_size, data }`。

## 一、需求概述

1. **定流量自动输送**：用户在前端选择「进水端水槽 → 出水端水槽」、水泵编号、目标累计升数，
   后端自动开启对应水泵，按累计流量达到目标升数后自动关泵。
2. **历史计时数据**：对上述输送任务做列表展示，按「水泵编号 + 时间范围」筛选，
   列表包含进水端、出水端、水泵编号、目标累计流量值、水泵运行时间。
3. **完成弹窗**：任务达标后前端弹窗「定流量任务已完成」（纯前端行为，后端只需在达标时置 `status = done`）。

## 二、前置需补齐的能力

| 能力 | 说明 |
|---|---|
| 执行器字段名 | 把 `pump2`（及用户自定义的其它泵）登记为 `category:'actuator'` 字段，`/monitor/device/control` 即可收 `{ "pump2": 1 }`。只登记字段名即可 |
| 累计流量 totalizer | 新增全局累计升数 `flow_total`（单位 L）。二选一：<br>① 在 `/monitor/sensor/latest` 返回体里加 `flow_total`；<br>② 单开 `GET /api/monitor/flow/total` 返回 `{ code:0, data:{ flow_total: 123.4 } }` |

> **物理前提**：目前只有一个 `flow`（L/min）流量计，后端没有「水槽 / 方向」概念。
> 累计采用「全局 `flow_total` + 任务级基线做差 + 同一时刻只允许一个运行中任务」来保证不串量。
> 若以后分方向有独立流量计，再拆成 `flow_total1` / `flow_total2`，接口不变。

## 三、任务记录字段（一张表，自动输送 + 历史共用）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 任务 id |
| `source` | string | 进水端（前端水槽 id / 名称，后端只存不解析） |
| `target` | string | 出水端 |
| `device` | string | 水泵编号（执行器字段名，如 `pump` / `pump2`） |
| `target_liters` | float | 目标累计流量值（L） |
| `start_total` | float | 本次基线（创建时读到的 `flow_total`） |
| `accumulated_liters` | float | 实际累计 = 当前 `flow_total` − `start_total` |
| `runtime_seconds` | int | **水泵运行时间**（秒）：`done/stopped/failed` 时为 `finished_at − started_at`，`running` 时为 `now − started_at` |
| `status` | string | `running` / `done` / `stopped` / `failed` |
| `started_at` | string | 开始时间 |
| `finished_at` | string | 结束时间（进行中为 null） |

## 四、接口

### 4.1 创建任务（开始输送）

`POST /api/auto-transfer`

```json
// 请求
{ "source": "1", "target": "2", "device": "pump2", "target_liters": 5.0 }
```

```json
// 响应
{ "code": 0, "msg": "ok",
  "data": { "id": 1, "source": "1", "target": "2", "device": "pump2",
            "target_liters": 5.0, "status": "running",
            "start_total": 12.3, "accumulated_liters": 0.0,
            "runtime_seconds": 0,
            "started_at": "2026-09-18 16:00:00", "finished_at": null } }
```

后端行为：校验无运行中任务 → 记 `start_total` 基线 → 下发 `{ device: 1 }` 开泵 →
服务端循环读 `flow_total` 算增量 → `accumulated_liters >= target_liters` 时下发 `{ device: 0 }` 关泵、
置 `status = done`、填 `finished_at` / `runtime_seconds`。

### 4.2 历史计时数据列表（筛选 + 分页）

`GET /api/auto-transfer`

| 参数 | 必填 | 说明 |
|---|---|---|
| `device` | 否 | 水泵编号精确匹配（如 `pump2`），缺省查全部 |
| `start_time` | 否 | 按 `started_at` 筛选，`YYYY-MM-DD HH:MM:SS` |
| `end_time` | 否 | 同上 |
| `page` / `page_size` | 否 | 分页，缺省 `1` / `20` |

```json
// 响应（分页约定）
{
  "code": 0, "total": 37, "page": 1, "page_size": 20,
  "data": [
    { "id": 1, "source": "1", "target": "2", "device": "pump2",
      "target_liters": 5.0, "accumulated_liters": 5.02,
      "runtime_seconds": 186, "status": "done",
      "started_at": "2026-09-18 15:00:00", "finished_at": "2026-09-18 15:03:06" }
  ]
}
```

列表建议按 `started_at` 倒序。

### 4.3 查询进度

`GET /api/auto-transfer/<id>` → 单任务详情（data 结构同 4.1）。

前端每 1~2 秒轮询运行中任务的 `<id>`，刷新进度条和「已输送 / 目标」数值。
**任务完成后 `status` 置为 `done`，前端据此弹窗「定流量任务已完成」并播放提示音（无需后端新增接口）。**

### 4.4 手动停止

`POST /api/auto-transfer/<id>/stop` → 立即关泵，`status: stopped`，填 `finished_at` / `runtime_seconds`。

### 4.5 删除记录

`DELETE /api/auto-transfer/<id>` → 删历史记录（运行中任务需先 stop）。

## 五、任务完成通知（纯前端，后端无需改动）

- 后端达标时保证：`status = done`、`finished_at` 与 `runtime_seconds` 已填充。
- 前端轮询检测到 `status` 由 `running` 变为 `done` 时，弹出提示框「定流量任务已完成」，
  并复用现有 `playAlarmSound()` 播放提示音。

## 六、安全停机（后端必须做）

- **单任务约束**：全局只允许一个 `running` 任务，重复创建返回 `code != 0` 提示「已有进行中的输送任务」
- **零流量保护**：泵已开但连续 N 秒 `flow <= 0` → 关泵置 `failed`
- **超时保护**：单任务超上限仍未达标 → 关泵置 `failed`
- 关泵走后端可靠通道，**不依赖前端在线**

## 七、前端数据来源对照

| 页面 | 字段 | 来源 |
|---|---|---|
| 自动输送（建任务） | `source` / `target` | 前端 `tankList`（`iot_water_tanks`） |
| | `device` | 前端设备（执行器）列表 `devices`（`iot_water_devices`） |
| | `target_liters` | 用户输入 |
| 历史计时数据 | 水泵编号筛选 | `devices` 列表 |
| | 时间范围 | 现有 `RollTimeRangePicker` |
| | 列表列 | 进水端 / 出水端 / 水泵编号 / 目标累计值 / 运行时间（`runtime_seconds` 用 `formatDuration` 格式化） |

创建 / 列表（筛选分页）/ 详情 / 停止 / 删除 5 个接口 + 达标关泵循环。
